# Design — Otto

## Direction
Product: a Windows desktop notch that opens a Personal AI Assistant & Learning Mentor for in-place study, explanations, writing, and screen help; the shell also exposes one Settings surface.
Character: warm, quiet, precise, gently expressive — modern non-technical English interface copy with zero coding-IDE chrome.
World: a single dark instrument at the top edge of the working desktop (solid by default, with user-adjustable translucent background opacity via `--otto-surface-opacity`); the surrounding native window remains transparent and never paints a second backdrop.
Identity: the Compact shell is the Agent capsule; hover previews the composer directly without taking focus, and click/keyboard activation pins it. The Otto logo is identity only; the gear opens Settings. The Otto logo uses a fixed default expression; appearance preferences are not exposed. Keep chrome restrained, with no decorative module artwork or generic card layouts.
Per-surface moments and interaction graphs belong in the current PR/task, not in this durable file.

## Guardrails
- Tailwind CSS v4 is the default styling system: put static layout, alignment, spacing, and token colors in complete TSX utility classes; keep theme tokens and shared notch geometry in `src/style.css`. Do not duplicate layout declarations or construct utility names at runtime.
- `src/style.css` Tailwind `@theme` is the executable token source: surface/text/muted, `--font-otto-ui`, `--radius-otto-island`, `--ease-otto`. Reuse tokens and Tailwind's 4px spacing scale; do not scatter semantic literals in components. Add accent, controls or extra scales only with real usage.
- UIArc is a visual reference, not a dependency. Prioritize real provider/session/status content over ornamental effects; never simulate successful AI or capture states.
- Icon source: use `lucide-react` through `src/shared/ui` for native controls, preserving the repository's component abstraction and accessible names. Keep icon mapping and accessible names in the shared UI boundary.
- Keep the visible native surface limited to the Agent capsule, Agent composer, and settings surfaces; omit fake desktop windows, explanatory panels, secondary studies, and decorative lab chrome. Keep behavior, geometry, and settings in the owning React/Tauri surfaces.
- Agent composer: stays as a clean one-line capsule at idle (`Ask Otto anything…`); when the prompt wraps, adds lines (up to five lines), or holds staged capture/pasted attachments and contextual Quick Action chips, it becomes a rounded stacked composer. The composer hosts a quiet Learning Mode pill (`Direct`, `Solve`, `Mentor`, `Simple`, `Write & Translate`, `Practice`) with `/slash` triggers, a Camera control with a quick visual-source menu (`Region snip`, `Last focused window`, `Scrolling window`, `Full screen`), and Send/Stop (plus a quiet queued follow-up pill when a follow-up is staged during streaming). Keep permanent provider/model dropdowns out of the composer; Engine, Model, and Thinking effort live in Settings → Assistant and are quickly reachable via a compact popover from the clickable Header label. Let conversation height grow to a capped notch, then scroll internally with visually hidden scrollbars; never fabricate runtime metadata.
- Agent answers render as Markdown (`.md-body` / prototype `.af-md`): text-first lines with 4px vertical rhythm, `md-h` headings at 14/13/12px, token-colored inline code, list/quote/table/task-list styles from `src/style.css` tokens, `.katex` scaled to body text. Fenced code is a `CodeBlock` figure — deep-ink body on `--color-otto-ink-deep`, mono 10px, uppercase language label header, and a per-block `Copy code` action reusing `CopyAnswerButton`. Raw HTML/script from answers is never executed; unknown fenced languages show the raw label escaped; streaming answers render safe partial blocks. Optional formatting loads on the first nonempty assistant answer; until it loads, or for the process lifetime after a load failure, show the latest source as inert, wrapping plain text. Whole-answer Copy and Agent controls remain available under their existing gates; per-block copy appears with formatting. Completing formatting never takes focus; size changes follow the bottom only when the reader was already following. The current Agent surface and `src/style.css` tokens are the visual reference for the formatted surface.
- Settings has a single entry, the gear in the Agent header; the Otto logo is not a button. No Home route or module launcher is part of the shell.
- Smooth notch motion: one top-centered, interruptible silhouette stage inside a stable native host driven by Otto OS's 2nd-order damped spring curve (`response 0.30s, damping 0.84` via `--ease-otto`), with one effective duration (`features/shell/model/motion.ts` → `--otto-morph-duration`): Fluid 260ms, Subtle 200ms, Reduced 0ms; height-only adjustments cap it at 170ms, and a first content measurement arriving during a running expand morph preserves the remaining morph instead of snapping to 0ms. Stage and numeric radii inherit it; Floating Compact uses its exact numeric half-height pill radius (`height / 2`, never `9999px`) and tactile 3% press compression (`response 0.12s, damping 0.92`, 150ms independent of morph duration), while Expanded keeps 18px card corners; Attached keeps a flat top, concave shoulders and only rounded bottom corners. Center-anchor both outgoing and incoming shell frames horizontally inside the morphing silhouette; preserve outgoing mounted content until its exit completes (95ms compact-to-expanded, 110ms expanded-to-compact, 150ms page cross-slide), reveal expanded content from `opacity: 0` with an 8px rise after the ~45ms shape threshold, slide Agent/Settings/History transitions 24px horizontally with crisp exponential easing, and crossfade Settings tab content (~160ms) without scaling text. Docked Otto OS follow uses the same 2nd-order spring physics (`response 0.26s, damping 0.86`) in Rust (`shell/otto_os.rs`). Host/display revisions invalidate obsolete frame reports; ordinary page/Compact navigation never grows or shrinks the HWND. Attached shoulders follow the stage outside its body, never wrapper/content padding. Only active natural content can resize it; normalize heights to confirmed physical pixels without 8px buckets. Preserve ~150ms hover intent and ~340ms leave grace without adding remaining morph time; confirm current pointer hit before collapsing after a layout-induced leave. Reduced motion uses `data-reduced` plus `src/style.css` to disable descendant transitions/animations. Settings keeps the parent Agent controller and active CLI run alive.
- Floating and top-attached placements preserve the same available tasks; neither may create an invisible hit area that blocks unrelated desktop actions.
- Hover can reveal a preview but never takes keyboard focus. Only an explicit activation opens the interactive surface; dismissal returns attention to the prior desktop task. Keep Expanded is the inverse of stored clickOutside; it changes pinned blur only, not Preview or Escape. After Escape collapses the surface, layout-generated pointer events cannot reopen it while the pointer remains over Otto; hover rearms after a confirmed leave, and explicit activation remains available. Hide Otto from screen capture defaults ON and reports confirmed Windows affinity, not optimistic UI; static design references cannot claim native capture protection.
- Background Agent updates never force surface navigation or keyboard focus. A completed run uses a quiet status affordance that the user can open.
- Compact/expanded morphs preserve identity and content continuity; any gesture has a visible and keyboard-operable equivalent. No mandatory animation blocks an action.
- Do not reuse public-web LCP/INP/CLS as desktop quality targets. Observe Windows/WebView2 input, frame pacing, and resource behavior under representative conditions.

## Frontend visual baseline
- Mac Native is the only sizing system; there is no Default version or sizing selector. Old saved sizing selections are ignored without resetting other preferences. Rust `notch_sizing.rs` resolves Agent and settings sizes from native display geometry; `src/style.css` owns 13px body / 11px secondary text, 13px Compact and 18px Expanded shell corners. Compact Agent is 228×40; Expanded Agent is 526×170–610 (content-dependent and capped by display height). A measured camera housing adds a non-content top band to every Attached surface; Floating starts below the native menu/safe area. No scaling, module copies or state resets. Physical-Mac appearance, menu-bar behavior and native input remain unverified until device acceptance.
- **Single source of truth:** `.agents/DESIGN.md` is the durable design contract, while the current React/Tauri implementation and `src/style.css` are the executable visual reference. Compact/Expanded Agent, Settings, Floating/Attached placement, and their navigation each have one owning source surface. Every UI change must inspect this contract and the affected source/state owner, preserve approved states, sizes, controls and motion unless explicitly changed, and update this file when the design contract changes. Do not generate or revive standalone HTML references. Source and native runtime evidence outrank sketches or screenshots; never propagate invented success states.
- Agent is the only feature module. Compact is the Agent capsule; hover opens its composer directly. Settings is a secondary surface, not a launcher.
- Floating: centered below the screen top edge by default, with a saved custom position available by dragging the panel. Placement settings expose Reset to default. Attached: connected to the top edge through symmetric concave shoulders and rounded bottom corners, not a capsule simply cut off at the top. Keep the same information and actions in either placement; preserve an accurate native click/hit region. The reference adds ~12px shoulder per side, subject to Windows verification.
- Otto OS coexistence (Windows): while the Otto OS top bar (`OttoNotchBar`) exists, Otto yields the top edge. Attached is not applied and the saved placement preference returns when Otto OS closes. Appearance matches the Otto OS notch: solid obsidian black (`--color-otto-obsidian`) with a 14% white rim, for every surface. Docked (default, no saved custom position): Otto is a circle as tall as the notch, inside the bar, 8px right of the Otto OS island (the notch plus its Focus/Media circle). It reads the live island rectangle Otto OS publishes (`OttoOS.NotchRect` window property) and glides to follow it while the island morphs, pausing while a pointer button is held. Hover expansion is off while docked; click or the shortcut opens it. Otto re-raises itself above the Otto OS bar when covered. Undocked: dragging Otto out of the bar saves a custom position, hover expansion returns, and the circle stays free; releasing it inside the bar zone (bar plus 16px below) snaps it back to the docked slot. Without a published rectangle (older Otto OS) the circle is 40×40 at the top center below the bar. Detection, glide, z-order and the dock signal are Rust-owned (`platform/windows/otto_os.rs`, `ipc/notch.rs`); Windows runtime acceptance with a rebuilt Otto OS is pending.
- Placement geometry (implemented): `--otto-shoulder: 12px`, `--radius-otto-attached: 18px` and `--radius-otto-expanded: 18px` are the single visible source. Attached sits flush (`y = monitor top`), adds `2 x 12px` shoulder width to the native window and insets the rendered frame by the same amount; its flare and rounded bottom corners are **outside** the native hit region, so a shoulder can never intercept an unrelated desktop action. `Top offset` applies to floating only when no custom position is saved. Both placements expose identical content, actions, keyboard paths and dismissal; floating drag and Reset to default preserve the same host and hit-region rules; a placement Windows refuses keeps the reported placement and offers retry.
- **Reference sizes (logical/CSS px; tune against WebView2/DPI, not Apple point measurements):** Agent 228×40 → 526×170–610 (content-dependent, capped by display height); Settings 526 wide, height hugging the active section (minimum set by the sidebar, about 271) up to the host cap. Attached shoulder width is additional to the content body, and measured camera-safe content insets apply to every surface.
- Spacing: follow 4px rhythm; Compact horizontal padding around 10–12px, content-to-control gaps 8–12px; Expanded outer padding around 16–20px, group gaps 8–12px. Preserve icon/text baseline and constrain conversation overflow inside the card. Circular controls keep their intended shapes; no gratuitous nested borders, filler subtitles, or oversized empty panels.
- Compact Agent: use Otto's logo as the stable identity mark; show observed provider/status and activity bars only while thinking or streaming. In Otto OS compact circle mode, keep the logo expression fixed and signal observed state inside the circular silhouette: an inner orbital sweep while capturing, thinking, or streaming, a persistent semantic inner rim and status pip for non-idle states (`completed`, `attention`, `error`, active work), and a one-shot inner accent ripple plus micro-motion on state transitions (disabled cleanly under reduced motion). Expanded Agent keeps the current provider/model header (status lives in the conversation), transcript, history and capsule composer. Hover changes no focus and does not start an Agent run.
- Settings (one surface, 526px wide): the Agent gear is the only entry; the Otto logo is identity, never a second settings button. A left sidebar with five sections: Assistant, Capture, Behavior, Position and General. Five sections is past the tab threshold, so a sidebar (icon + label, arrow-key navigation) is used, and Settings reopens on the last section; the capture entry opens Capture with the shortcut focused. The header is Back + "Settings" only; section names are never repeated as headings (a screen-reader heading carries the name). Height hugs the active section up to the host cap and the content pane scrolls inside, so it shrinks as well as grows; the sidebar sets the minimum. Every row follows one pattern: label (+ one short hint only when it adds information) on the left and a single control on the right (`SettingRow`); stacked controls use `SettingBlock` (label above a full-width control, optional trailing action). No dividers between congruent rows; spacing carries grouping. Switches, choices and shortcuts apply immediately and there is no Save button anywhere. Shortcuts (Selected Text capture, Visual Capture, expand/collapse) share the same key recorder (click, press keys, Esc cancels, invalid combinations get a specific hint, Reset appears only when changed). Status text appears only when it is not the happy path (a ready engine is a small badge on its label, a healthy capture setting shows nothing). Assistant: AI Engine chips (installed first, Refresh PATH action, the rest behind "Not installed (N)"), Model with Refresh models, Thinking effort with a one-line speed-vs-depth hint, Context usage, and a concise static **Profile & Learning Style** block (preferred answer language, level/tone, brief instructions). Capture: Default visual capture source (`Region snip`, `Last focused window`, `Scrolling window`, `Full screen`), independent **Selected Text shortcut** and **Visual Capture shortcut**, and an **Instant auto-send** toggle (default OFF — staged-first in composer). Behavior: Expand on hover, Keep expanded, Shortcut. Position: Placement (Floating/Attached, Attached disabled with a reason), Top offset only for the default position, Reset only for a custom one. General: Background (`Solid` / `Transparent` with manual `Opacity` slider 30–95%), Hide from screen capture, Updates, Quit Otto. No logo expression customization, taskbar control, hover-timing, custom preset CRUD, or motion-profile controls are exposed. Persistence, Windows-native placement, hit areas and reduced-motion behavior require separate verification.
- Agent: use the current Agent components and this contract as the approved quiet-first composition. Compact shows observed engine/status and activity bars **only** while thinking/streaming. Expanded keeps a quiet clickable engine/model Header label (also toggleable via `Ctrl+M`, opening a compact popover to switch Engine, searchable/pinnable Model, or Thinking effort without leaving chat or hiding cached models during background refresh) with History, New Chat, and Settings controls, a scrollable transcript (with a helpful Empty State offering 3–4 light learning/assistant starters and shortcut hints), persistent History access (supporting open, continue, full-text search, rename, delete, and Export Markdown), and one progressive-disclosure capsule composer. All run, capture, and readiness state lives in the conversation: a non-technical live activity trail (`Thinking`, `Searching`, `Reading context`, `Writing answer`, `Stopping` — never developer jargon such as `Editing files` or `Running a command`) capped at the last four steps while active, plus an optional collapsible **Thinking** block (collapsing cleanly above the turn's answer for the active session, never persisted to disk history), and stopped/error notices (preserving already-streamed partial text when stopped). Staged captures (Region Snip, Window, Scrolling, Full Screen, Selected Text) and pasted/dropped images (`Ctrl+V`) appear as removable attachment chips with contextual Quick Actions (`Explain`, `Break down`, `Translate`, `Summarize`, `Quiz me`, `Rewrite`); pressing Enter with an empty draft runs the default action. Completed answers expose Copy, **universal Insert** (targeting the validated last focused external caret, never the clipboard), Retry/Regenerate, Edit prompt, a subtle muted response-time meta indicator on the latest completed turn, and 3–4 quiet learning follow-up chips (`Simpler`, `Give an example`, `Quiz me`, `Go deeper`) beneath the latest completed turn only. If an engine pauses for a host permission decision, show a lightweight inline choice card (`Decline & continue` / `Allow once`, never auto-approved). Keep permanent dropdown bars, coding workspace selectors, diff views, and filler panels out of the notch.
- Agent event motion: subtle activity bars only for actual CLI work; one-shot completion feedback and brief error shake are acceptable when event-driven. No idle loop, simulated progress, approval cue, focus theft or excessive bounce. Settings stay inside the island; reduced motion preserves use without animation.
- Motion: top-center shell anchor, coherent silhouette width/height/radius interpolation, left-aligned Agent identity, delayed content reveal, and interruptible collapse/expand. The native host stays fixed while revisioned physical silhouette regions keep transparent margins click-through; during a morph the region is the union of the applied and target silhouettes sent once up front, then replaced by the measured silhouette when the stage settles, never per frame; content motion stays transform/opacity-only. Prototype spring-like ease, ~150ms hover intent, and ~340ms pointer-leave delay are tuning references, not Windows performance claims. Animate transform and opacity for content; the one width/height animation allowed is the silhouette stage inside the preconfigured stable host, whose inner content keeps the target layout so nothing reflows; a control's press feedback must not inherit the morph duration. Hover may expand without stealing focus; explicit click/keyboard activation pins the composer until dismiss/Escape. Respect reduced motion.

## State
- UI-local: shell owns an exclusive Compact/Preview/Pinned mode and the active Agent/settings surface plus focus intent; Agent owns its unsent prompt. Keep these near the owning feature, not in a global catch-all store.
- Native: placement, bounds, foreground/capture capability and focus policy are Rust-owned; UI reflects observed capability, not presumed success.
- Agent: provider readiness, provider/model/thinking selection, run/conversation/output, local history, cancellation, and capture lifecycle are Rust-owned. Collapsing or changing features never implicitly stops a run; stale events never overwrite a terminal result.
- Async variants are truthful and actionable: pending retains meaningful context; errors preserve drafts and explain recovery; denied/unsupported is distinct from success; stopped/interrupted is distinct from completed. Never render invented answers or recoveries.

## Patterns
- Entry: Compact Agent capsule → non-focusing hover preview opens the Agent composer → explicit click/keyboard activation pins it → dismiss/Escape returns to Compact. The hover-only composer closes after pointer leave without stealing focus; required actions have a keyboard path. Treat the top-edge island as a desktop overlay, not a normal web route.
- Agent is the only module; there is no Home launcher, module carousel, wheel routing, or Alt+Left/Right page switching. Settings is the only secondary surface. Preserve provider context before AI submission.
- Behavior: the Expand / collapse shortcut (default Ctrl+Alt+O) is recorded with the shared key recorder and applies immediately with error-only feedback. It toggles Agent between Compact and pinned Expanded, collapses Preview and suppresses immediate hover reopening; it never hides the native window. Preserve meaningful errors and capture-protection caveats. System reduced motion remains automatic; canonical HTML cannot validate native global input.
- Otto is a Personal AI Assistant & Learning Mentor without its own edit/shell executor or coding workspace selector. Underlying CLI behavior stays with each engine; a host permission request pauses inline with an explicit `Decline & continue` / `Allow once` choice and is never auto-approved.
- Popovers (header Engine/Model/Thinking switcher, composer Camera visual-source menu, `/slash` mode menu) follow focus-owning overlay semantics: keyboard navigable, Escape closes and restores focus to the trigger without collapsing the pinned notch.
- Use an expanded interactive surface for sustained reading and conversation history. Use non-interactive status for passive completion; it must not steal focus.
- Error and empty states name the unavailable capability and offer the next valid action (retry, configure, choose provider, or dismiss). Disable a temporarily unavailable action with a reason; hide actions that can never apply.
- Per-feature U/M/ST/V/N graph and X# recovery mapping stay in the implementing PR. Do not turn this file into a screen-by-screen specification.

## Component reuse and motion source
- Use [Arc UI](https://uiarc.dev/) as the preferred **component and interaction-motion source**, not a replacement for Otto's visual identity. Before creating reusable controls, inspect the upstream component and reuse its maintained, compatible source when that reduces duplication; adapt appearance through Otto tokens and this contract. Respect upstream licensing and dependency lockfiles. Do not introduce a parallel design system.
- Prefer Arc's documented snappy / smooth / morph / responsive motion presets once adopted. State changes drive animation; preserve interruptibility and reduced-motion behavior. Keep motion configuration at its owner rather than scattering magic durations across JSX.
- Provider and lifecycle states are backend contracts, not free-form strings. Render labels, tones and motion through feature-owned presentation policies; capability availability comes from the provider adapter, never from a visual-only provider enum or a pretend success.

## Frontend composition rules

Enforced by `bun run check` → `scripts/frontend-rules.mjs` against `.agents/frontend-budget.json`. The budget is a **ratchet**: a change may lower a number, never raise it. Fix the violation; do not edit the baseline upward.

```text
R1  no raw color literal in any src/**/*.{ts,tsx}       0
R2  no color literal in CSS outside the @theme block    <=107 (shrink as modules are tokenized)
R3  largest component file, lines                       <=202
R4  features missing a public index.ts entry            0
R5  total Biome diagnostics                             <=17
R6  aria-label attributes                               0 (render the name instead)
R7  hand-drawn <svg> outside src/shared/ui              0 (use shared/ui icons)
```

Build every screen block by block, component by component, from shared primitives; do not grow one file into a screen.

```text
src/shared/ui/     Icon (lucide), Eyes,
                   IconButton (variants: outlined | raised | quiet | round | primary),
                   VisuallyHidden, StatusMessage (tone + optional action),
                   Text (display | heading | title | body | label | meta | caption | status | code),
                   ChoiceGroup (chip | row), Range, Toggle
src/features/
  shell/           preferences, useNotchShell, GlobalSettings
  agent/           AgentPanel (container)
                   AgentCapsule, AgentSettings, AgentTranscript, History, Bars
                   surface.ts (surface + compact copy), status.ts, useAgent
src/platform/      typed Tauri transport
```

- **Layers**: `ui` (render-only, props in / events out) ← `feature` (state, effects, IPC) ← `data` (`src/platform`). `ui` never imports `feature`; components never call the Tauri transport directly.
- **Shared primitives** live in `src/shared/ui` and appear at the third real reuse, not the second. A repeated control (icon button, choice chip, range, toggle, status marker) is a component, not a copy of the same CSS rule and inline SVG.
- **Feature modules**: one directory per capability with a public `index.ts`; import a sibling feature only through that entry.
- **File size**: a component file that stops being a component gets split by responsibility (panel, card, controls), never by line count. `noExcessiveLinesPerFunction` / `noExcessiveCognitiveComplexity` are Biome warnings that count toward R5 — extract, do not suppress.
- **Icons**: real icon set, `lucide-react` pinned by the lockfile. `shared/ui` maps a role name (`settings`, `alert`, `terminal`) to the component; features never import lucide directly and never draw an `<svg>`.
- **Accessible names**: an icon-only control carries real text, hidden with `VisuallyHidden` (or `IconButton`, which pairs both). Do not use `aria-label`; a dialog or region is named by its visible heading via `aria-labelledby`. Icons are `aria-hidden` decorative glyphs — the name belongs to the control.
- **Status text** is derived in one place (`features/agent/status.ts`, `surface.ts`), not by nested ternaries at each render site.
- **Styling**: static layout/spacing/token colors are Tailwind utilities in TSX; `src/style.css` owns executable theme tokens and shared geometry; `src/styles/` owns feature-level selectors, artwork and motion. Semantic colors come from `@theme`; add a token rather than a new literal.

## Quality targets
| Gate | Metric / target | Evidence |
| --- | --- | --- |
| UG1 Reachability | 100% of in-scope B# map to an operable M# → U# path; addressable views have navigation if the app actually supports deep links/back | Design graph in feature PR |
| UG2 Recovery | 100% of in-scope X# have a visible, recoverable V#; no dead-end retry or false success | Flow review and targeted behavior proof |
| UG3 Ownership | Exactly one authoritative owner for each consequential ST#; no UI copy of Rust agent/run truth | Compare graph against engineering S# |

| UG5 Focus safety | 0 unsolicited focus or active-feature changes on hover, pending work, background completion or collapse | Focus/active-view transition observation |
| UG6 Responsiveness | Observe p95 action-to-visible response and frame intervals during active CLI streaming and notch morphing; numeric targets TBD until a Windows baseline (Q1/Q2, A2/A7) | Representative Windows build, not browser-only animation |
| UG7 Idle cost | Measure idle CPU and private memory for Otto + WebView2 separately from CLI processes; numeric targets TBD until baseline (Q1/G5) | Windows process-family observation |

These are product/interface gates, not a request for new CI workflows, standalone test plans or invented benchmark pass results.

## Accessibility
- Baseline WCAG 2.2 AA: text contrast ≥ 4.5:1 for normal text, non-text UI/indicators ≥ 3:1; interactive targets ≥ 24×24 CSS px or satisfy the applicable spacing exception.
- Every essential move is keyboard-operable with visible focus. Hover has an equivalent explicit control; focused overlays have an exit and valid focus restoration.
- Important async results and validation failures are perceptible through visible status and appropriate announcements; passive status does not hijack focus.
- Honor `prefers-reduced-motion`: remove nonessential morph/translation and preserve the same usable state changes without animation.
- Platform contrast, pointer hit area, focus restoration and capture exclusion require representative Windows verification; a Vite render is not native proof.
