# Engineering — Otto

## System
Windows-first Tauri 2 modular monolith: React presentation (K1) → narrow Tauri controller (K2) → Otto Rust core (K3) ← CLI/persistence adapters (K4); Windows platform adapters (K5) implement native effects. Core owns state, contracts and permissions. Existing code implements Assistant-only provider streaming/capture; Coding Mode and provider-neutral history are design targets, NOT shipped. Native signed-in/OS capture acceptance remains unverified; Music is an event-driven Windows-media projection pending native acceptance, while Focus has an in-process Rust timer runtime, IPC contract, and K1 Compact/Expanded control surface.

## Structure
Current K1 is feature-first: `src/App.tsx` composes the Shell, Agent, Music, Focus and OS Events hooks, `AppView.tsx` routes surfaces, `features/{shell,agent,focus,home,music,os-events}` owns UI behavior, `platform/tauri.ts` owns native transport and IPC DTOs, and `shared/ui` owns genuinely reusable controls. Music and Focus mount their app-lifetime snapshot subscriptions in `App`; their features own presentation, with Focus additionally owning pending phase-discard confirmation.

Target **within the existing modular monolith**, introduced incrementally only when that behavior is changed:
```text
src/
  main.tsx                  composition bootstrap
  App.tsx                   compose feature controllers; coordinate native surface
  ShellContent.tsx          choose the expanded/compact surface for ShellView; no native effects
  AppView.tsx               page-to-view rendering only
  features/
    shell/
      index.ts               public feature API
      useNotchShell.ts       shell facade (navigation, focus and preferences composed)
      preferences.ts         validated local preferences
      surface.ts             pure surface resolution
      [navigation.ts]        only when extracted/tested shell transitions need an owner
    agent/
      index.ts               public Agent API
      useAgent.ts            facade over narrow hooks; no CLI policy enforcement
      useCaptureSource.ts    existing source selection lifecycle
      [useAgentConnection.ts]    snapshot channel and reconnect
      [useAgentRequests.ts]      submit/stop/history/draft reconciliation
      [useCaptureShortcut.ts]   registration/target status
      status.ts, surface.ts, view-model.ts
      Agent*.tsx, Transcript*.tsx, History*.tsx
    home/
      index.ts, HomeSurface.tsx, HomeCard.tsx
    focus/
      index.ts, useFocusTimer.ts, focus-connection.ts, focus-actions.ts
      FocusCapsule.tsx, FocusPanel.tsx, Focus*.tsx, view-model.ts
    os-events/
      index.ts, useOsEvents.ts, OsEventCapsule.tsx, view-model.ts
  platform/
    tauri.ts                 sole Tauri command/event transport boundary
  shared/ui/                stateless reusable controls, no feature imports
  assets/, style.css        art and semantic tokens
```
Square-bracket paths are **proposed extractions, not current files or a mandate to create empty folders**. Keep existing Agent/Settings visual components as-is; the problem is lifecycle ownership, not insufficient UI nesting. Do not introduce app-wide stores, generic services, repositories, or extra layers without a second concrete consumer.
Rust shape (implemented): K2 IPC lives in `ipc/{agent,focus,media,notch,overlay,os_events}.rs` (one bounded context per file) and notch surface geometry in `notch.rs`; K3 `agent/` is `model.rs` (values) plus `runtime/{connection,selection,readiness,capture,run,session,history_ops}.rs` (one lifecycle owner each) over `conversation.rs`, `policy.rs`, `events.rs`, `history.rs`; K3 `focus/{model,runtime}.rs` owns deadline-derived timer state and its app-lifetime publication loop; K3 `media.rs` owns the ephemeral projection cache and ordered subscribers; K4 `agent/providers/` shares one `transport.rs` process/JSONL primitive with per-provider protocol adapters; K5 `windows/` owns native effects, including the Windows media-session worker. Split further only with a changed responsibility and proof, not pre-created file trees.

- **K1 (frontend):** `App.tsx` is the composition root; only feature hooks and the root coordinator invoke `src/platform/tauri.ts`. Render-only TSX receives explicit narrow view contracts and callbacks, not native effects; no feature imports a sibling's internals. `AppView.tsx` should eventually depend on a stable exposed feature view model rather than `ReturnType<typeof useAgent>` or `ReturnType<typeof useNotchShell>`.
- **Agent facade rule:** `features/agent/useAgent.ts` remains the public composition facade and owns no new authoritative state. Its internal lifecycle hooks are split by existing ownership and side-effect lifetime: connection/snapshot subscription, provider readiness, capture shortcut/source, and request/submission actions. `useAgentHistory` remains its existing history boundary; `App` and `AppView` keep the facade contract while extraction proceeds.
- **Focus facade rule:** `features/focus/useFocusTimer.ts` is the public composition facade. `focus-connection.ts` owns the app-lifetime subscription/reconnect lifecycle, `focus-actions.ts` serializes IPC mutations, and presentation components receive only snapshots plus callbacks. The shell owns Focus page routing; `FocusPanel` owns only pending phase-discard confirmation. A snapshot update must never navigate or focus a surface.
- **Frontend bloat rule:** split a file only at a state owner, side-effect lifetime, dependency boundary, or independently testable user journey. Do not mass-split cohesive markup or create generic `helpers`/services to reduce line counts. The same facade rule applies to `useNotchShell`; its candidate seams are navigation/hover, preferences, native placement/capture readback, and focus lifecycle. `ShellContent` remains a composition boundary until one surface needs independent behavior proof.
- **K2 (controller):** `lib.rs` composes implementations; `ipc/` maps and validates IPC and delegates to the core or the owning module, never to policy or CLI protocol internals; notch sizes, bounds and placement math belong to `notch.rs` and native application to `windows/`.
- **K3 (Otto core):** `agent/mod.rs` is the composition root (re-exports, `AgentRuntime` construction, recovery start); lifecycle owners are R2 `runtime/run.rs`, R2 admission `runtime/readiness.rs`, R2/R9 `runtime/capture.rs`, R7 `runtime/selection.rs` + `policy.rs`, R8 `conversation.rs` + `runtime/history_ops.rs` + `history.rs`, R2 routing `runtime/connection.rs`. Own port/event contracts; never import native Codex/Pi/Agy/Win32 implementation.
- **K4 (infrastructure):** `agent/providers/` contains Codex/Pi/Agy transport/readiness/session/process adapters; local `history.rs` implements R8 persistence. Registry names adapters, not domain policy.
- **K5 (Windows):** `windows/` owns foreground, hotkeys, capture, overlay and resource cleanup; capture must not import AgentRuntime or submit model turns (D6).
- **Dependency direction:** `App → features/{shell,agent,focus,home,os-events} → shared/ui`; feature controller → `platform/tauri.ts → Rust commands` (one-direction runtime calls); platform never imports feature presentation. Public feature `index.ts` is the cross-feature seam; feature internals remain private. Keep TS DTOs co-located with the IPC bridge until actual independent consumers justify splitting contracts.
- **Refactor constraint:** boundary-only extraction preserves existing Assistant behavior; Coding is a separate explicit capability only after security proof. Extract one responsibility/test-backed slice at a time; no empty folders, new crates or full rewrite.

## Responsibilities
- R1 (B1,B2,B10): present idle/compact/expanded state, navigation, active feature, drafts, unobtrusive completion and keyboard/focus intent.
- R2 (B3,B8,B13,X1,X4,X10): own provider-neutral run/turn lifecycle, event ordering, Stop and recovery; delegate conversation persistence to R8 and native protocol/session to K4.
- R3 (B4,X2,X6,X8): explicitly triggered capture, external-window target validation, hotkey conflicts, supported image submission and temporary-file cleanup.
- R4 (B5,X3): observe system media/lyrics availability, show accurate playback state and handle supported controls.
- R5 (B6): configurable focus/break timer, monotonic deadline, pause/resume/reset.
- R6 (B1,B2,B7,B10,X5): own native window position, pointer region, always-on-top, focus, capture affinity and best-effort suppression from supported capture source pickers via Windows tool-window style.
- R7 (B9,B11,B13,X7,X9,X12): own mode and runtime capability admission, scoped authorizations and pre-effect approval policy; Assistant tool-free, Coding verified tool scope/approval or deny.
- R8 (B3,B14,X10,X13): own Otto conversation identity, transcript and history independent of runtime; distinguish actual native resume from saved-context reconstruction.
- R9 (B4,B13,X2,X6): prepare text/image/workspace context with explicit capture consent; OS implementation belongs to K5, not AI lifecycle.
- R10 (B15,X14,X15,X16): own OS event normalization, coalescing, priority, expiry and truth rules; K5 observers only report confirmed state and never own presentation or policy.

## State
- S1: selected page and exclusive Compact/Preview/Pinned mode | owner Shell hook (R1/React) | background updates cannot select a new page or take keyboard focus; hover timers may request Preview but never pin without explicit activation. Stored clickOutside controls only pinned blur collapse (inverse Keep Expanded UI), not Preview or Escape. Shell preferences have one React writer and validated localStorage mirror; native bounds are owned by S2.
- S2: placement, native bounds, focus policy and capture affinity | owner R6 (Rust) | no implicit activation on hover. Win32 owns actual display affinity and reports current state via IPC readback; exclusion starts ON and only confirmed changes update saved React preference. Tool-window picker suppression remains a separate best-effort mechanism. Placement is also observed, not assumed: the surface command applies bounds plus the silhouette region and returns `floating|attached` read back from the window (region present and top edge at the monitor origin), and the UI persists only that observed value.
- S3: run/turn state | owner R2 (Rust) | single authority, run_id/seq ordering, one terminal outcome and rejection of late events; UI Snapshot is a projection, not independent authority.
- S4: selected runtime/model/thinking and verified capability | owner R7 (Rust) | lock selections during a run; model capability is verified per adapter; never persist credentials or native session IDs.
- S9: Otto conversation ID/transcript/history | owner R8 (Rust) | bounded versioned JSON, single writer, atomic replace/corruption recovery; provenance per run; expand/migrate/contract compatibility; limited reconstruction must not claim native resume.
- S10: provider-native session/child process | owner K4 adapter | ephemeral, owned per runtime, cancelled/closed on Stop/exit, never portable conversation authority.
- S11: selected mode and scoped permissions | owner R7 (Rust) | Assistant denies model tools; Coding default deny unless scope and pre-effect authorization verified.
- S12: current OS event, per-class last value, expiry and publication gate | owner R10 (Rust) with S1 preference input | single active event; UI is a read-only projection; no history or persistence; observers publish only confirmed changes, never an initial snapshot.
- S5: target window, capture request and image lifetime | owner R3 (Rust) | explicit invocation provenance, still-valid non-Otto target, no send on ambiguity/denial; sensitive images are ephemeral with Drop cleanup on finish/error/cancel. After a crash, startup may delete only named capture files aged >=24h when the owning PID is confirmed exited; unknown/active PIDs and unrelated files are preserved. Best effort, not secure erasure.
- S6: media observation | owner R4 (Rust cache; OS is source of truth) | an observed current session atomically replaces the old projection; controls are gated by the observed session capabilities and update only after a new observation; no fabricated lyrics/sessions; ephemeral, no permanent media history.
- S7: focus/break duration, timer deadline and paused state | owner R5 (`FocusTimerRuntime`) | `Instant` deadline is authority and remaining time derived; one in-process runtime publishes revisioned snapshots over K2 and sleeps while idle; pause freezes remaining time, duration changes update a ready session or take effect at its next session, active phase replacement requires explicit discard, and nothing persists across app exit unless preference storage is explicitly introduced.
- S8: unsent chat draft, provider/model/thinking selection, transient connectivity, capture settings and history UI operations | owner Agent hook (R1/React) | submitted drafts are correlated with accepted run IDs; history list/open/rename/delete use one feature-owned AgentHistoryController with an exclusive pending operation and stale-result protection. Rust S3/S4/S5/S9, not UI state, authorize provider capability, capture, active-conversation reset and persistence. Unsent draft remains memory-only.
- Concurrent writes: one active run owner serializes run transitions; independent background completions update their own data, never S1. UI events are observations, not independent authoritative copies.

## Contracts
- K1 -> K2: typed Tauri command `submit/stop/provider_status` (names illustrative until implemented), input validation and bounded payload; immediate outcome = accepted run_id or recoverable error. Rendering the UI cannot authorize OS side effects.
- K1 -> K2 lyrics: `media_set_online_lyrics(enabled)` grants/revokes session-only consent; `media_lyrics(refresh)` derives all query metadata from S6 and returns `{key, record}`. Rust rejects absent permission and mismatches; UI generations and the returned track key reject stale results, without navigation/focus effects. Lyrics view is UI-local, with Player/Lyrics/Escape navigation and 444x212 native geometry.
- K1 -> K2 media: `media_snapshot` and ordered `media_subscribe`/`media_unsubscribe` expose a read-only `MediaSnapshot`. Every `media_control` requires `expectedTrack`, the displayed source/title/artist/album/duration/session-revision identity; R4 re-observes and rejects mismatched, unavailable, unsupported or out-of-range actions before dispatch. Worker session revisions distinguish replacement sessions with identical metadata. IPC evolves with the frontend; missing identity fails closed. Windows offers no atomic compare-track-and-control, so a track change inside the native call remains a native acceptance limitation. No automatic command retry or optimistic playback state. K1 owns one generation-guarded subscription; manual Retry reconnects a failed subscription before refreshing, and a snapshot cannot clear a live-connection error.
- K2 notch geometry: `notch_set_surface(surface, shape, top_offset, duration_ms, content_height, content_only)` validates an allowlisted silhouette (`capsule|card|attached`), applies bounds plus the Win32 window region, and returns the observed placement. Attached reserves `2 x 12px` shoulder width and ignores `top_offset`; floating keeps the rectangular window and no region. A command that cannot apply or read back the requested silhouette fails closed instead of reporting success.
- K2 -> K3: validated mode/run request → R7 pre-dispatch admission; Assistant is tool-free; Coding tool effects need proven scope and pre-effect approval, otherwise fail closed; UI choice alone cannot authorize effects.
- K3 <-> K4: core-owned normalized request/events (`run_id`, seq, text/tool/usage/terminal), readiness/capabilities and cancellation; adapter owns native protocol/session and rejects unsupported features. No universal ANSI parsing or silent runtime fallback.
- K3 -> K1 OS events: typed `os_events_subscribe`/`os_events_unsubscribe`/`os_events_set_enabled` returning confirmed `OsEventView` values over an ordered channel; K1 owns Compact-only suppression and never treats rendering as authorization.
- K3 -> K1: ordered Tauri channel for run output and terminal outcome; separate low-frequency notifications may use events. Sequence/run_id guards ignore late, duplicate or stale output; Stop is idempotent for that run. UI collapse neither stops nor detaches the run owner.
- K1 rich transcript boundary: the Agent transcript may load Markdown, KaTeX and code-highlighting resources on demand after the Agent surface or rich answer is needed. The boundary preserves inert HTML, safe links, code-copy behavior and math fallback; a failed optional load must not lose the transcript or alter R2 run state.
- K1 shared identity: `OttoLogo` owns the Expanded Home logo geometry and `OttoHomeButton` preserves the named Home action. `OttoLogoProvider` supplies a read-only shell-preference projection to all module headers; it owns no state or persistence. Idle Compact continues using `Eyes` directly.
- K1 shared UI boundary: `shared/ui` exposes stateless controls through its public entry; individual control files may be split for ownership/readability, but the public API and token source remain stable. Splitting `Field.tsx` or `ShellContent.tsx` is a maintainability change, not a bundle optimization.
- K3 -> process boundary: K4 launches executable with argument array (no shell interpolation), owned tree lifetime, bounded untrusted I/O and cleanup; Assistant has no workspace selector, Coding has explicit verified scope. Windows suspended-start Job Object constrains lifetime, NOT filesystem permissions.
- K3 -> K5: core-owned context/capture port carries validated explicit user intent; Windows returns capture result or recoverable error, cleans ephemeral resources, and must not directly call AgentRuntime (existing D6).
- Compatibility: same-process IPC evolves together; durable history expands/migrates before old format is retired and retains rollback readability; runtime switching never implies native-session portability.
- DEP1: Windows WebView2 | reuse OS runtime | missing runtime prevents UI, show installer/runtime remediation | availability bound: OS installation | exit cost: switching Tauri UI stack.
- DEP2: Codex/Pi/Agy executables | reuse user install/auth | absent, version drift, auth expiry, or unavailable chat-only capability = explicit recoverable state | availability bound: local CLI/provider service | exit cost: per-provider adapter rewrite.
- DEP4 (B5/X3): LRCLIB HTTPS lyrics lookup | reuse public API, no credentials/backend | offline, mismatch, malformed/oversized payload or rate limit preserves playback with recovery | optional availability only | replace the bounded lyrics adapter. Online lookup is OFF at each app launch and requires explicit consent disclosing title/artist/album/duration egress; no audio, credentials or listening history is uploaded/persisted. Rust checks permission, uses the current observed track, exact normalized identity plus duration ±2s, 3s connect/8s request limits, 512 KiB response cap, no redirects and Retry-After cooldown. One serialized lookup and one ephemeral cached result; stale track/permission results are rejected. Only line timing is currently rendered; no synthetic word timing.
- DEP3: Windows window/capture/media APIs | reuse OS | unsupported or blocked = capability-specific degradation | availability bound: Windows/version/recorder | exit cost: native integration rewrite.
- Provider-side conversations/logs and model transmission follow each CLI/provider policy; Otto cannot promise their deletion.

## Flows
- Existing bootstrap (B1): process launch -> K5 Windows per-session named mutex (duplicate exits before Tauri initialization; error fails closed) -> K2/K5 frameless WebView -> K1 idle. The handle remains open for the process lifetime and Windows reclaims it on exit/crash; normal WebView2 subprocesses are unaffected.
- Existing Assistant flow (B2,B3,B8,B9,B10,B11,X1,X4,X7,X9,X10): select provider/model → verified tool-free readiness → accept R2 run → K4 CLI stream → R8 saved history → collapse/reopen or Stop → quiet completion.
- Capability break (B9,B13,X7,X12): Assistant tool/approval event terminates before continuation; Coding unsupported sandbox/approval denies action before effect, preserving draft/recoverable status.
- Coding target (B13,X12): select Coding + workspace → R7 prove scope/approval and capability → R9 context → R2 accepted run → K4 pre-effect tool authorization → allowed effect/result or explicit denial.
- Cross-runtime history (B14,X13): finish/stop run → preserve R8 conversation → close K4 session → select runtime/model → reconstruct bounded persisted messages or disclose missing native context.
- New Chat (B9): after a terminal run, user explicitly resets the conversation from the Agent chat header beside Settings -> R2 closes and waits for the owned provider process -> persists old history, creates a new conversation, and clears runtime transcript. An active run cannot be reset implicitly.
- Interruption (B8,X4,X10): collapse/switch = continue; Stop = cancel owned run and reject late output; app exit = terminate owned child work; crash/restart = show only independently verifiable provider history, otherwise interrupted/unknown.
- Capture (B4,X2,X6,X8): explicit hotkey -> R3 verifies assigned shortcut + pinned non-Otto target + capability -> capture -> user-chosen provider receives image -> response -> delete temp. Invalid/denied -> nothing submitted.
- Media (B5,X3): K5 binds the current Windows media session and its change notifications -> R4 publishes its sanitized ephemeral projection -> K1 shows observed state/absence -> supported playback action -> K5 re-observes state; missing lyrics remains explicit and no background update selects Music or changes focus.
- Timer (B6): configure -> R5 records deadline -> derived remaining time -> pause/resume/reset/start-next -> revisioned K2 snapshot -> quiet observation via R1.
- Shell (B1,B2,B7,B10,X5): R6 positions/requests capture protection -> K5 applies the silhouette region for attached or clears it for floating -> R1 renders -> hover preview no focus theft -> user activation controls focus/expanded state -> background updates do not select a new view; unsupported capture exclusion is disclosed. The motion profile selects the single morph duration used by both the CSS silhouette and the K2 warp.
- OS events (B15,X14,X15,X16,Q7): K5 observer reports a confirmed change -> R10 normalizes, sanitizes and applies priority/dedupe/expiry -> ordered subscription channel -> K1 renders only while Compact and no run is active -> auto-dismiss restores the previous Compact surface; dropped while Expanded or during a run.

## Guarantees
- G1 (B4,Q5,C6) [H]: without an explicit user capture action, no image is captured/submitted; SLI unauthorized capture/send invocations = 0 per invocation trace at R3 boundary (no image logging).
- G2 (B3,X4) [H]: after Stop or app exit, owned CLI process-tree survivors = 0; Windows Codex children are attached to a kill-on-close Job Object and launch fails closed if attachment fails. Assignment occurs after spawn, so wrapper pre-assignment races and crash behavior still need representative Windows proof.
- G3 (Q2) [M]: navigation/Stop remain responsive while CLI is busy; SLI p95 input-to-view response and frame intervals at WebView/host; target TBD from A2, no invented latency SLO.
- G4 (B1,B7,X5) [M]: UI remains accessible even when tool-window styling or capture affinity is unsupported; R6 verifies HWND style bits while actual picker omission and protected capture must be observed with representative Windows recorders. No universal exclusion guarantee.
- G5 (Q1) [M]: measure idle CPU/private memory of Otto+WebView2 process family separately from CLI and capture p95 frame intervals during morphing at OS/WebView; targets TBD from A2.
- G12 (Q1,C3,B1,B11) [M]: Compact does not initiate provider readiness CLI subprocesses; canceled probes own process-tree cleanup, and reopen uses a short verified-result cache while Rust revalidates every actionable request.
- G6 (B9,C7) [H]: Assistant launches no tool-capable native model session without verified disabled-tool admission; SLI unauthorized Assistant tool-capable launches = 0 at R7.
- G7 (B8,X10) [H]: collapse/switch never cancels or loses an accepted run; SLI implicit cancellations on UI-only transitions = 0, observed at R2 run state and K1 event reconciliation. Restart must not fabricate completion.
- G8 (B9,B13,X7,C7) [H]: Assistant tool/approval attempts cannot continue; Coding without verified grants never reaches side effects; SLI unauthorized effect continuations = 0 at R7/K4 pre-effect boundary.
- G9 (B10,Q4) [M]: background completion does not change active feature or take keyboard focus; SLI unsolicited focus/active-view changes = 0, measured at R1/R6 transitions.
- G10 (B11,X1,X9,Q3) [M]: absent/unauthenticated/unsupported providers cannot accept runs; SLI accepted requests with invalid readiness = 0, measured at R7 validation/submit boundary.
- G11 (J1,Q6) [M]: user can obtain, persist, reopen, and reuse an answer without launching another app; SLI successful ask -> history reopen -> follow-up -> return-to-origin journey on a Windows walkthrough; success threshold not yet set (A7).
- G13 (B14,X13,C8) [H]: runtime/model switch never changes persisted Otto conversation identity or claims fake native resume; SLI false native-continuity claims = 0 at R8/UI history projection.
- G14 (B13,X12,C7) [H]: unapproved/out-of-scope Coding side effects = 0 at proven pre-effect runtime/OS enforcement; unsupported enforcement disables the action.
- G15 (B15,Q4,Q7) [M]: OS events never change the active page/feature or take keyboard focus; SLI unsolicited focus or active-view changes = 0 at R1/R10; idle cost measured with G5 and no polling beyond the documented brightness interval and battery reconcile.
- G16 (B15,X14,X16) [M]: a rendered OS event matches the last confirmed native observation; SLI fabricated or unverified state renders = 0 at the R10 publish boundary, and sanitized native text never reaches logs.
- G17 (B7,Q4,X17) [M]: the native notch window covers only the rendered silhouette. SLI silhouette point mismatches = 0 at the K5 region readback boundary (shoulder corners, rounded corners and body samples agree with the intended geometry); attached keeps `y = monitor origin`, `width = body + 2 x 12px` and ignores the floating offset. Click pass-through to the window beneath the shoulder corners still requires representative Windows acceptance.

## Challenge
| H flow | Failure / threat | Blast radius | Containment | Detection signal | Recovery |
| --- | --- | --- | --- | --- | --- |
| G1 capture | implicit trigger, wrong target or sensitive image sent | screen privacy | only explicit hotkey; pin/recheck target; capability gate | R3 send provenance vs action | reject capture, delete temp, ask user to retry |
| G2 agent exit | CLI descendants remain alive, stale stream after Stop | local tools/resources and misleading answer | owner-scoped process tree; terminal run state | R2 process exits, surviving descendants, late event count | terminate owned tree, mark run cancelled |
| G6 chat-only | provider flag ignored/unsupported, tool-capable session starts | local tools/files | deny unknown capability, require proven tool-free provider mode | R7 policy outcome vs adapter launch | refuse provider, show chat-only limitation |
| G7 continuity | UI unmount/collapse drops stream or cancels CLI | active conversation | run owned outside view; replay buffered current result by run_id | R2 transition and K1 resubscription gap | resubscribe/reconcile, mark interrupted only if genuinely lost |
| G8 unsafe event | adapter accidentally continues after tool/approval event | filesystem/tool side effects | reject every unsafe event and terminate run | R7 rejection vs provider continuation | block action, terminate child, notify user |
| G13 portable history | native session lost or incorrectly claimed after provider switch | conversation trust | R8 transcript + labeled reconstruction | R8 provenance and UI | reopen saved messages, disclose lost context |
| G14 Coding effects | tool acts before approval or outside scope | local files | deny if runtime/OS scope or pre-effect grant unverified | enforcement trace | reject and terminate request |
| G15/G16 OS events | false connect/charge state, focus theft, notification storm | misleading status, interrupted work | confirmed-read-only observers, hub dedupe/TTL, Compact-only suppression | R10 publish vs native observation; focus/view transitions | emit nothing, expire event, restore prior Compact surface |

## Decisions
- DEC1 [one-way]: owner chose Tauri 2 + React/Vite/Tailwind + Rust/Bun over native Slint for faster UI iteration. Trade-off: WebView2 process/memory and window composition behavior; revisit only if representative Q1/Q2 measurements show a material problem.
- DEC14 [two-way] (G12,P7): keep one WebView and persistent chat event subscription/hotkey; readiness probes use a Rust-owned, request-ID cancellation gate and frontend 60-second ready-only cache. Cancel drops the bounded CLI probe future and its Windows Job Object, never the live chat transport. Refresh bypasses cache; Rust verifies new requests and captures, except that a completed, still-owned Agy chat transport with identical provider/model/thinking/capture context can send follow-ups directly. Agy reports auth expiry and other failures from each live turn; a failed/disconnected transport cannot reuse this exception.
- DEC2 [two-way]: one modular desktop app and feature-owned states over additional service/global store. Trade-off: in-process crash affects the shell; revisit for proven isolation need.
- DEC3 [two-way]: provider-specific structured protocols and ordered run channels over generic terminal text/events for high-frequency streaming. Trade-off: more adapter work; revisit with real CLI protocol constraints.
- DEC11 [two-way] (B3/B9/C7): Pi runtime catalog and selected-model capability come from isolated JSONL RPC; full provider/model IDs preserve nested slashes. Model/thinking are confirmed before each request; session token statistics remain best-effort and do not fabricate context counts. Pi launches `pi --mode rpc --no-session --no-tools --no-extensions --no-mcp --no-skills --no-prompt-templates --no-context-files --no-approve`. Only model/auth-verified chat requests can run; screenshots use Pi RPC `prompt.images` (Base64 PNG), with selected-model image capability required before capture and again before submission. Provider/model/thinking changes are locked during an active run. Capture uses a separately owned native selection confirmed through readiness; previous answer metadata is not overwritten by UI selection. Follow-up setup is interruptible before prompt submission and stale usage is cleared at turn acceptance. Tool-free transport is required but is not an OS sandbox.
- DEC12 [one-way] (B3/B9/C7): Provider scope is Codex, Pi, Agy only; OpenCode is removed. Agy uses a dedicated tool-free custom agent (no inherited MCP/customizations) and native JSONL stream; Rust checks the selected agent identity and exact allowed tools from headless init before any prompt. Agy screenshots fail closed; official stream-json input accepts only text blocks. CLI model discovery and init are readiness probes, not live model-turn evidence; Windows signed-in prompt, follow-up, Stop, and process cleanup still require acceptance before release.
- DEC4 [two-way]: Windows 11 native APIs, Tauri content protection, untitled main HWND and WS_EX_TOOLWINDOW over switching UI frameworks for source-picker suppression. Untitled tool windows are skipped by some WebRTC enumerators; filtering is caller-specific and cannot guarantee universal exclusion. Trade-off: missing native window title affects accessibility/discoverability; preserve visible Otto UI and revisit if tested pickers still enumerate the HWND.
- DEC5 [one-way] (G6,G14): enforce mode/capability/effect permission in Rust/native runtime, never only in UI/prompt. Assistant tool-free; Coding needs verified pre-effect scope/approval; Job Objects/read-only flags alone do not enforce it.
- DEC6 [two-way]: Otto stores versioned local text conversation history in app data, but never provider credentials, screenshots, cwd, or provider thread IDs. Atomic JSON avoids a new database dependency until history volume proves it necessary.
- DEC7 [one-way] (B9,B13): Assistant excludes tool execution/workspace write/approvals; Coding becomes a distinct future mode with verified scoped tools and user authorization. Existing adapters remain Assistant-only until P15 passes.
- DEC8 [one-way] (B9,B13,X7): Assistant rejects native tool/approval requests; Coding may map native pre-effect approval to Otto grant without exposing native request IDs; no auto-approval or retrospective authorization.

## Release
- On every merge/push to `master`, the Windows `release` workflow automatically plans a version, verifies frontend/Rust on Windows, builds one NSIS installer and publishes a GitHub **prerelease** with SHA-256 checksum; no manual dispatch, extra release branch or additional PR. Only successful required steps publish.
- Versions derive from immutable reachable `vX.Y.Z` Git tags (first base: aligned `0.1.0` source manifests): `feat` or breaking change -> 0.x minor; `fix`/`perf`/`revert` or an unknown commit -> patch; docs/chore/ci/build/test/refactor/style alone -> no new release. Highest change since the prior tag wins. Squash PR titles should use Conventional Commits.
- Source `package.json`, `Cargo.toml` and Tauri config retain the aligned base version; release workflow stamps the selected app version into the Tauri configuration **only in the checkout**. The tagged `master` SHA, locked dependency inputs, CI version stamp and immutable installer checksum identify the release. No bot commits or recursive workflows.
- Bun install is frozen and Cargo checks use `--locked`; check, frontend behavior tests, Rustfmt, Cargo check/test and Clippy must pass before bundling. GitHub Release notes are automatically generated from merged history. Unsuccessful runs do not publish. Prevent tag reuse, concurrent publication and unverifiable installer output.
- Until real authenticated Windows Agent/capture/Stop acceptance and Authenticode code signing are established, the automated GitHub Release is marked prerelease, not stable. The NSIS installer remains unsigned for Windows SmartScreen purposes, while Tauri updater artifacts are minisign-signed for in-app update verification. The updater reads `latest.json` from the dedicated `updates` branch (written only after an immutable GitHub prerelease is published) on launch and every six hours, and Global Settings offers the user-triggered quiet installation in NSIS current-user scope; the GitHub Actions `TAURI_SIGNING_PRIVATE_KEY` secret is required for every release build.
- The sparse MSIX identity artifact is not a second published installer or updater lane. It can be built locally for capability validation, but it must be signed by a certificate whose subject matches `OTTO_MSIX_PUBLISHER` and registered against the actual NSIS install directory before a release can claim package identity or Windows global-media acceptance.
- Recovery preserves known-good compatible installers; an immutable published version is never repointed. Fixes ship via a new higher version (roll-forward); reverting binaries alone does not reverse provider-side actions or local state.
